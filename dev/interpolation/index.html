Interpolation

Supply finite, increasing sites. Matrix ordinates use one independent function per column, sharing the same sites. Plans cache geometry-dependent work, not the answer for every future ordinate array. In particular, Akima coefficients depend nonlinearly on values and must be recomputed when those values change.

using AbstractCosmologicalEmulators
t = [0.0, 0.3, 0.8, 1.4, 2.0, 3.0]
q = [0.1, 0.7, 1.2, 2.8]
u = 2 .* t .+ 1
expected = 2 .* q .+ 1
for make_plan in (AkimaSplinePlan, CubicSplinePlan, CubicBSplinePlan)
    plan = make_plan(t, q)
    @assert isapprox(plan(u), expected; atol=1e-12)
end
expected

 1.2
 2.4
 3.4
 6.6

Cubic B-splines

The high-level B-spline API implements not-a-knot interpolation, not a smoothing fit. It needs at least four sites. Endpoint knots have multiplicity four and the internal knots are t[3:end-2]. The interpolation sites determine the knot vector; custom knots or basis objects are deliberately not high-level constructor options.

values = hcat(t .^ 3, 2 .* t .+ 1)
plan = CubicBSplinePlan(t, q)
result = plan(values)
@assert size(result) == (length(q), 2)
@assert isapprox(result[:, 1], q .^ 3; atol=1e-12)
@assert isapprox(result[:, 2], 2 .* q .+ 1; atol=1e-12)
result
4×2 Matrix{Float64}:
  0.001  1.2
  0.343  2.4
  1.728  3.4
 21.952  6.6

A scalar query returns a scalar for vector ordinates, or a series vector for matrix ordinates. A query vector returns a vector or a query-by-series matrix. Splines and plans own snapshots of their source/query geometry, even when the same array was supplied for both. Do not mutate stored geometry.

Extrapolation

The B-spline APIs accept these explicit policies:

PolicyOutside the interpolation domain
:clamp (default)Continue the nearest endpoint value
:throwRaise an error
:zeroReturn zero
julia> using AbstractCosmologicalEmulators

julia> t = [0.0, 1.0, 2.0, 3.0];

julia> s = CubicBSpline(2 .* t .+ 1, t; extrapolation=:zero);

julia> s(-1.0) == 0.0 && s(4.0) == 0.0
true

Endpoint equality selects the interior derivative. Dynamic :throw queries are not supported under Reactant; host-validated fixed-query plans can use it. Do not assume these B-spline policies are keyword options on Akima or cubic splines.

Apply coordinate transformations such as log.(k) yourself before constructing a spline. AbstractCosmologicalEmulators.jl does not silently change the interpolation variable or value scale.

Low-level basis operations

CubicBSplineBasis provides explicit basis construction and inspection: knot_vector, internal_knots, nbasis, bspline_domain, and basis_support. Basis evaluation uses basis_row, basis_stencil, basis_matrix, or bspline_basis. bspline_coefficients solves for coefficients. These are lower-level operations, not extra arguments to the high-level interpolator.

Chebyshev coefficients and reconstruction

chebpoints uses second-kind extrema (Lobatto) nodes, including both interval endpoints. Degree K means K+1 nodes, ordered from the upper endpoint to the lower endpoint. Keep values in that same order when forming coefficients.

This is Chebyshev-polynomial reconstruction, not a cubic spline through Chebyshev-distributed samples:

using AbstractCosmologicalEmulators
K = 8
nodes = chebpoints(K, -1.0, 1.0)
plan = prepare_chebyshev_plan(-1.0, 1.0, K)
values = nodes .^ 3 .- 2 .* nodes .+ 1
coefficients = chebyshev_decomposition(plan, values)
query = collect(range(-1.0, 1.0; length=31))
polynomials = chebyshev_polynomials(query, -1.0, 1.0, K)
reconstructed = polynomials * coefficients
@assert isapprox(reconstructed, query .^ 3 .- 2 .* query .+ 1; atol=1e-12)
maximum(abs.(reconstructed .- (query .^ 3 .- 2 .* query .+ 1)))
3.2612801348363973e-16

Create FFT plans outside repeated evaluations. Multidimensional plans take tuples of interval bounds/degrees; size_nd describes the full array and dim identifies the transform axes. See prepare_chebyshev_plan. The thread setting affects only FFT plans created after it is set.
