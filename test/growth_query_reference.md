# Frozen growth-query references

`growth_query_reference.tsv` freezes forward values and parameter gradients of
the public growth functions as produced by the code at commit `6c2caa3`, i.e.
**before** the growth-query AD repair. It is output from the package, not an
independent oracle: it guards that the repair leaves the fixed physical
pipeline and the existing parameter derivatives unchanged. Query-time
derivatives, which the old path lost, are validated independently in
`test_growth_query_ad.jl` (analytic ODEs, ForwardDiff and a test-only dense solve).

Columns (tab separated, one header row, 16 data rows):

```
species prescription  h omegab omegac omegak m1 m2 m3 w0 wa Neff  D1 D2 D3  f1 f2 f3  g1 … g10
```

- `species` is `CBGrowth` or `MatterGrowthApprox`; `prescription` is
  `temperature` or `radiation`. Each of the four combinations has four
  cosmologies: the fiducial massless case (zero masses, `Neff=3.044`), a
  curved, massive `w0wa` case, and two seeded random supported cases
  (`MersenneTwister(20261115)`).
- `x = (h, ωb, ωc, ωk, m1, m2, m3, w0, wa, Neff)` is the input; `D1..D3`,
  `f1..f3` are `D_f_z` at `z = [0.3, 1, 2.5]` with `reltol=1e-11`, `abstol=1e-13`.
- `g1..g10` is the prepared-Mooncake gradient with respect to `x` of
  `sum(D) + 0.37*sum(f)`.

Numbers are written with `repr` and parse back exactly. The test reads the file
with `split`/`parse` only (no evaluation).

Tests retain this file as the original forward anchor and historical gradient
record. Forward values are compared at `rtol=2e-10`, `atol=2e-12`.
The portable gradient assertion uses the refined pre-repair reference below,
with the **unchanged** acceptance threshold `|Δ| ≤ 1e-9 + 2e-8|g|`.

Provenance: Julia 1.12.6, Mooncake 0.5.67, SciMLSensitivity 7.106.0,
DiffEqBase 6.218.0, SciMLBase 2.155.2, OrdinaryDiffEqTsit5 1.12.0,
ForwardDiff 1.4.7. Generated by
`.letta/growth-query-investigation/freeze_baseline.jl`; its SHA-256 and the
other recorded inputs are in `.letta/growth-query-investigation/baseline-inputs.sha256`.

## Converged pre-repair gradient reference

`growth_query_reference_converged.tsv` has the same layout and exactly the same
16 input cases. It was generated from the preserved **pre-repair source**, not
from the candidate implementation, using `reltol=1e-14`, `abstol=1e-16` and the
same prepared-Mooncake loss. The generator asserts the preserved source path
and absence of the new `_growth_states_at` helper. Each case gets a fresh
preparation and a value check against the direct public evaluation. All 160
gradient components are cross-checked against the separate refinement run.
The dependency versions are the same as the original reference above.

Why refine rather than loosen the test? On the lower dependency stack, both
the old and repaired code produced **bitwise-identical** values and all 160
parameter derivatives, but both failed the original cross-stack gradient
threshold on eight nonzero-mass components in `MatterGrowthApprox`. The largest
difference was `8.9265265439814057e-9`. All ten complete `t/u/b/c/d` lookup-table
arrays were bitwise identical across stacks, excluding table construction as
the explanation in these runs.

Successive old-source refinements gave the following maximum absolute
cross-stack gradient differences over all 160 components:

| `reltol` | `abstol` | Maximum difference |
|---|---|---|
| `1e-11` | `1e-13` | `8.927e-9` |
| `1e-12` | `1e-14` | `1.324e-9` |
| `1e-13` | `1e-15` | `3.321e-10` |
| `1e-14` | `1e-16` | `5.464e-11` |

The final successive-refinement changes were at most `4.560e-10` on the lower
stack and `5.410e-10` on the original stack; all separate primal diagnostic
solves returned `Success`. Test evaluations use `reltol=1e-13`, `abstol=1e-15`.
Against the refined reference, those old-source evaluations consumed at most
0.332 and 0.362 of the original componentwise error budget, respectively.
`reltol=1e-12` still failed that budget, so the choice is evidence-based.
These are convergence checks for the stored cases, not a general bound on
sensitivity errors or proof of a particular spline-knot mechanism.

**Public solver defaults and every acceptance threshold remain unchanged.**
Both forward anchors are checked in the ordinary test suite. The original
coarser gradients are preserved for reproducibility, not overwritten or used
as a universal cross-version accuracy oracle.

Generation and calibration records:
`.letta/growth-query-integration/freeze_converged_baseline.jl`,
`gradient_convergence.jl`, `convergence-old-{lower,current}.{tsv,log}`, and
`convergence-summary.log`. The lower environment used SciMLSensitivity 7.95.0
and ForwardDiff 1.0.1; its exact manifests were compared to confirm that the
matched old/new test changed only the package source.
